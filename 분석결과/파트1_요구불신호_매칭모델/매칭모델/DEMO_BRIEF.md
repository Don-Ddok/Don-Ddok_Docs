# 마케팅 담당자 추천 화면 데모 — 작업 지시서

이 문서를 먼저 끝까지 읽고 작업한다. 아래 "반드시 지킬 것"은 레퍼런스 디자인보다 우선한다.

## 1. 무엇을 만드나
- **보는 사람:** 은행 마케팅 담당자. "이번 달 누구에게 어떤 상품을 제안할지"를 한눈에 보고 캠페인 대상을 고르는 화면.
- **데모 기준:** 2025-07, 경북. 수출 둔화 T0=2025-04, 적기 단계 첫 달(k=3). 외환노출 법인 342곳 (수출형 190, 수입형 152), 비노출 3,054곳.
- **디자인 레퍼런스:** 사용자가 Mobbin에 골라 둔 컬렉션(화면). Mobbin 도구로 사용자의 저장 컬렉션·화면을 먼저 확인한다. 불러올 수 없으면 추측해서 고르지 말고, 사용자에게 컬렉션 이름이나 화면 링크를 물어본다. 레퍼런스에서는 레이아웃·타이포·여백·색감을 가져오고, 구조와 기능은 아래 요구사항을 따른다.

## 2. 반드시 지킬 것 (사용자 요구사항)
### (1) 메인 화면의 3D 카드 → 클릭하면 업종별로 분류
- 메인 화면에 **3D 카드 요소**를 둔다. 해석한 흐름은 아래와 같고, 사용자가 다르게 원하면 사용자 의도를 따른다.
  1. **메인:** "2025-07 경북 · 적기 · 노출 법인 342곳"이 적힌 3D 카드 더미(스택). 살짝 기울어진 입체감, 호버 시 반응.
  2. **카드 클릭 → 업종별 분류:** 카드가 펼쳐지며 업종 카드로 나뉜다. 제조업 286 / 도매 및 소매업 35 / 건설업 8 / 기타 업종 13.
  3. **업종 카드 클릭 → 페르소나 분포:** 선택한 업종의 A~E 페르소나 카드. 제조업은 중분류(화학 38, 기계 37, 자동차 37 …)로 한 단계 더 펼칠 수 있다.
  4. **페르소나 카드 클릭 → 추천 패널:** 추천 상품(1~3개), 제안메시지, 추가요건, 이용경로, 근거_타이밍, "이미 보유 → 한도·조건 조정" 비율.
- **우리 매칭 모델이 그대로 드러나야 한다:**
  - 추천 상품·순서·제안메시지는 `demo_data.json`의 값만 쓴다. 상품이나 규칙을 새로 지어내지 않는다.
  - 수출형·수입형에 따라 A 결제형의 추천과 메시지가 달라지는 것을 보여 준다 (수출환 어음매입 vs 수입물품대도).
  - 같은 페르소나 × 세그먼트는 같은 추천을 받는다. 업종을 바꿔도 추천 상품은 같고 법인 수만 달라진다. 이를 숨기지 말고, 업종 화면은 "대상 규모", 추천 패널은 "무엇을 제안할지"로 역할을 나눠 보여 준다.
  - 단계 맥락(경북 적기, k=3)과 근거("수출 YoY 10%p 하락 시 외환노출 법인 요구불 누적 6개월 약 3.9% 감소", 2026-09-29 재검정 값)를 상단에 작게 표시한다.

### (2) 깔끔하게, 버튼 최소화
- 조작은 **카드 자체를 클릭**하는 방식으로 한다. 별도 버튼을 만들지 않는다.
- 뒤로 가기는 상단 **경로 표시 한 줄**(예: 경북 적기 › 제조업 › B 차입운영형)로만 한다. 경로의 각 항목을 누르면 그 단계로 돌아간다. Esc 키도 한 단계 뒤로.
- CTA 버튼·필터 바·탭·토글을 늘리지 않는다. 꼭 필요하면 사용자에게 먼저 묻는다.
- 색은 절제한다. 페르소나 5색 정도만 쓰고, 나머지는 무채색 + 강조색 1개.

## 4. 만드는 방식
- **결과물:** `C:\test\분석결과\matching\demo\index.html` 한 파일. 브라우저에서 더블클릭으로 열리도록 JSON은 HTML 안에 넣는다 (file:// 에서는 fetch가 막힐 수 있음).
- CSS 3D transform + 바닐라 JS로 만든다. 외부 라이브러리가 필요하면 먼저 사용자에게 묻는다.
- `prefers-reduced-motion`이면 3D 회전·펼침 애니메이션을 끄고 단순 전환으로 바꾼다. 카드는 키보드(Tab·Enter)로도 열 수 있게 한다.

## 5. 완성 전 점검
- 업종 카드 법인 수 합 = 342, 페르소나 합 = 업종 법인 수, 추천 패널 수치가 JSON과 일치.
- 수입형 화면에 "수출" 문구가, 수출형 화면에 "수입" 문구가 섞이지 않음 ("수출입"은 예외).
- 화면에 법인 ID·실제 잔액이 없음.
- 버튼 개수: 카드와 경로 표시 외에 클릭 요소가 없는지 확인.
- 브라우저로 열어 캡처해 보고, 겹침·넘침이 없는지 눈으로 확인한 뒤 사용자에게 보여 준다.
