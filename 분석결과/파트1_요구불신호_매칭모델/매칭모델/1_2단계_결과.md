# 상품 매칭 모델 1·2단계 결과 — 트리거 엔진, 세그먼트·페르소나

- 작성: 민영 / 2026-09-28 (2026-09-29 피드백 반영 수정)
- **이 모델이 하는 일:** 수출 둔화를 예측하는 조기경보가 아니다. **공식 수출 통계(K-stat)로 둔화 단계를 판정해 마케팅 제안 시점을 정하고, 은행 거래 데이터로 기업을 분류해 상품을 제안한다.** 은행 데이터로 둔화를 예측하지는 않는다 (포착률 재검증 결과 은행 신호의 포착률은 무작위 수준, `민영_포착률보정.md`).
- 목적: 규칙 기반 매칭 모델에서 "언제(1단계)"와 "누구에게(2단계)"를 정한다. "어떤 상품을(3단계)"은 확정된 상품표(`im뱅크상품\기업상품_매핑.csv`)와 다음 단계에서 연결한다.
- 근거 (재검정, `분석결과\민영_β합검정.md`): 수출 YoY가 10%p 하락하면 외환노출 법인의 요구불예금은 6개월 뒤까지 누적 약 3.9% (95% CI 1.6~6.2%), 12개월 뒤까지 약 5.0% (1.8~8.1%) 감소한다 (β₁+β₃, 법인·월 이중 군집, Holm 보정 후 h=2~12 유의, 사전추세 h=−3·−2 유의하지 않음).
  - 수치는 ln(요구불+1)을 t−1에서 t+h까지 누적한 로그 변화 ×100이다 (월별 감소율이 아니고, 잔액 0원은 +1로 처리). "수출 10%p"는 수출 YoY가 10%p 내려간다는 뜻이다 (수출액 10% 감소가 아님).
  - 이전 문서의 "6개월 4.2%, 12개월 5.2%"는 팀 코드(`beta1_common.py`) 결과인데, 그 코드는 β₁+β₃의 p값·다중검정 보정을 하지 않았고 의존 파일이 없어 재실행할 수 없다. 같은 식의 복사본 결과로 바꿨다.
  - 노출과 비노출의 **차이**(β₃)는 Holm 보정 후 h=6~8에서만 유의하다. "비노출은 반응 근거가 없다(β₁ 유의하지 않음)"만으로 두 집단 차이가 모든 시차에서 유의하다고 말할 수는 없다.
  - 이 근거는 요구불 반응에 대한 것이다. 상품 적합성·대출 승인·마케팅 효과를 보여 주지 않는다.

## 1단계: 트리거 엔진 (언제)

### 규칙 (사전 고정)
- **수출 YoY:** 지역 수출액의 단순 % YoY. 영업일수 전년차 성분을 대구·경북 공통 기울기로 뺀다 (영업일 1일당 +4.46%p, 상관 +0.45).
  - 단위: 영업일수 전년차 1일당 수출 YoY +4.46%p. 대구·경북 72개 지역×월을 합쳐 기울기 하나로 추정했다 (지역별로 따로 추정하기엔 지역당 36개월로 짧음).
  - 표7 재확인 문서의 +4.56%p와 다르다. 두 달력(자체 작성·workdays 파일)으로 다시 계산해도 트리거 기준은 4.458이라 달력 차이는 아니다. 표7 쪽 입력 수출 시계열 차이로 보이며, 매칭 모델은 4.46을 쓴다.
  - 보정 방식은 포착률 재검증 때와 같다 (`adjust_export_phase` 재사용).
  - 영업일수는 자체 작성 달력이다 (보고서 달력과 24개월 r=0.72로 사실상 일치).
- **둔화 시작월 T₀:** 보정 YoY가 2개월 연속 음수가 된 첫째 달 (**소급**). 실제 운영에서는 둘째 음수 달 통계가 나와야 알 수 있어 최소 1개월 늦고, K-stat 발표 시차만큼 더 늦어진다.
- **평시 복귀월 (이전 표기: 종료월):** 보정 YoY가 2개월 연속 양수가 된 둘째 달. 이 달부터 평시이고, 둔화 마지막 달은 그 전달이다.
- **재시작:** 둔화 중에는 새 T₀를 만들지 않는다. 종료 뒤에만 다시 찾는다.
- **단계:** k = 이번 달 − T₀.
  - 관찰 k=0~2 / 적기 3~6 / 정점·유지 7~12
  - 둔화가 계속되면 k≥13은 장기둔화
  - 둔화가 아니면 평시

**규칙 변경 1회 (13개월 상한)**
- 처음에는 T₀+13에 둔화를 끝내고 같은 달에 새 T₀를 허용했다.
- 13개월 상한은 근거(β 경로 h≤12) 범위를 표시하려던 것이지, 새 둔화 구간을 시작하려던 게 아니다.
- 그런데 긴 하락이 쪼개져서 하락 중간에 "관찰"이 생기는 문제를 발견해 수정했다.
- 지금은 k≥13이면 "장기둔화"로 표시하고 둔화를 유지한다.

- 좌측절단: 경북 첫 구간은 관측 시작월(2023-01)에 T₀가 잡혔다. 실제 둔화는 2023-01 전에 시작됐을 수 있으므로 "2023-01 시작"이라고 단정하지 않는다. 이 구간의 k와 단계도 실제보다 이르게 잡혔을 수 있다.

- 첫 번째 양수 달은 아직 둔화로 남는다 (예: 대구 2025-05, 보정 YoY +6.2%인데 장기둔화).

### 페르소나 규칙 (노출 법인만)
페르소나는 **보유 계정과 상품 이용 형태로 붙인 거래 유형(대리 지표)**이다. 실제 자금 필요를 확인한 것이 아니다 (예: B 차입운영형이라고 자금 부족이 확인된 것은 아님).

위에서부터 처음 해당하는 것이 주 페르소나다.
1. **A 결제형:** 할인어음 + 무역금융 잔액 > 0
2. **C 설비투자형:** 시설자금대출 잔액 > 0
3. **B 차입운영형:** 순수운전자금 > 0 (= 운전자금대출 − 할인어음 − 무역금융)
4. **D 현금비축형:** 거치식 + 적립식 잔액 > 0
5. **E 요구불중심형:** 나머지

주 페르소나와 별개로 보조 태그 `보유_A~보유_D`(Y/N)를 둔다. 비노출 법인은 페르소나 없이 업종_대분류로만 구분한다.

**규칙 변경 1회 (잔액 비교 → 보유 여부 + 우선순위)**
- 처음 기준은 "잔액이 가장 큰 계정군"이었는데, 노출 법인의 65.1%가 B에 몰렸다.
- 원인 1: 여신_운전자금대출잔액이 할인어음·무역금융을 포함하는 합계 계정이라 A가 B를 이길 수 없었다.
- 원인 2: 대출과 예금을 잔액 크기로 비교하면 규모 차이로 대출 쪽이 항상 우세했다.
- 그래서 잔액 비교 대신 보유 여부와 우선순위로 바꿨다.
- 기준 재조정은 이번이 마지막이다 (사전 합의). 새 기준으로는 60%를 넘는 페르소나가 없다.

## 코드 구조와 설정값

**trigger.py:** 입력은 ext_region·ext_bizday, 출력은 `trigger_stages.csv` (지역×월). 설정 상수는 파일 맨 위에 있다.

| 상수 | 값 | 의미 |
|---|---|---|
| `PERIOD` | 2023-01~2025-12 | 출력 기간 |
| `NEG_RUN` / `POS_RUN` | 2 / 2 | 둔화 시작·종료 연속 개월 수 |
| `MAX_K` | 12 | 근거 범위, 넘으면 장기둔화 |
| `STAGES` | 관찰 0~2, 적기 3~6, 정점·유지 7~12 | 단계 구간 |

출력 컬럼: 지역, 연월, 원YoY, 보정YoY, 둔화여부, T0, k, 단계, 좌측절단.

**persona.py:** 입력은 df_ready. 출력은 아래 네 파일이다.
- `persona_firm_month.csv`: 법인×월, **로컬 전용**
- `persona_snapshot_202512.csv`
- `persona_trend.csv`
- `persona_demand_median.csv`

| 상수 | 값 | 의미 |
|---|---|---|
| `WINDOW` | 12 | 세그먼트 판단 창 (당월 포함) |
| `PERSONA_ORDER` | A → C → B → D (나머지 E) | 페르소나 우선순위 |
| `HOLD_THRESHOLD` | 0 | 보유 기준 (잔액 > 0) |
| `CONCENTRATION_LIMIT` | 60% | 쏠림 기록 기준 |
| `COL` | 실제 컬럼 이름 | 예: 업종_대분류, 업종_중분류, 운전_할인어음잔액 |

- 세그먼트 컬럼 이름은 `세그먼트`, 값은 수출형 / 수입형 / 비노출이다. 상품표의 데이터필터가 이 이름과 값을 그대로 쓴다.
- 법인×월 결과 파일의 컬럼: 법인ID, 연월, 지역, 업종_대분류, 업종_중분류, 세그먼트, 페르소나, 보유_A~D, 요구불잔액, 창부족플래그.
- 이 md에는 집계만 넣었다. 법인 ID와 개별 잔액은 로컬 결과 파일에만 있다.
