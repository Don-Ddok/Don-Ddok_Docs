## 아이디어 4: 라벨 기반 검증 (신호 적중률)

### 왜 지금 못 하는가
지금 데이터에는 연체·부실·거래축소 같은 "실제로 나쁜 일이 일어났다"는 라벨이 없다.
자금압박지수(아이디어1)가 진짜 위험을 잡아내는지 확인하려면 사후에 무슨 일이
일어났는지가 있어야 하는데, 그게 없으니 지금은 "그럴듯해 보인다" 이상을 주장할 수 없다.

### 확보되면 어떻게 검증할 것인가

1. **라벨 정의**: 아래 중 은행이 실제로 가진 것 하나를 "부실 이벤트"로 정의.
   - 연체 발생(예: 30일 이상 연체) 여부·시점
   - 여신 한도 축소/회수 여부
   - 거래 급감(예: 전체 거래금액이 특정 임계 이하로 3개월 이상 지속) 여부
   - (실무적으로는 은행 내부 조기경보/부도예측모형의 기존 라벨을 그대로 재사용하는 게 가장 빠름)

2. **신호 시점 정의**: 아이디어1의 압박지수가 법인별로 임계(예: 상위 10%)를
   넘은 첫 달을 "신호 발생월"로 기록.

3. **추적 윈도우 설정**: 신호 발생월 이후 N개월(예: 3, 6, 12개월) 동안 라벨
   이벤트가 실제로 발생했는지 관찰. N은 여러 값으로 민감도 분석.

4. **혼동행렬 구성**:
   - True Positive: 신호 발생 + N개월 내 실제 이벤트 발생
   - False Positive: 신호 발생 + N개월 내 이벤트 없음
   - False Negative: 신호 없음 + N개월 내 이벤트 발생
   - True Negative: 신호 없음 + 이벤트 없음
   - 법인×월 패널이므로, 이미 이벤트가 발생한 법인은 그 이후 관측을 어떻게
     처리할지(이탈로 볼지, 회복 후 재관측할지) 미리 규칙을 정해야 함.

5. **지표 산출**: Precision = TP/(TP+FP), Recall = TP/(TP+FN), 그리고 임계값을
   바꿔가며 Precision-Recall 곡선 또는 ROC-AUC까지 확장 가능.

6. **베이스라인 비교**: "아무 신호 없이 무작위로 같은 비율만큼 찍었을 때"의
   Precision과 반드시 비교 — 그래야 압박지수가 실제로 정보를 담고 있는지 판단 가능
   (STEP22 위약검정과 같은 논리).

7. **주의할 함정**:
   - 라벨 자체가 은행의 사후 대응(한도축소 등)으로 발생했다면, 압박지수와
     라벨이 같은 원인(매출 하락)에서 동시에 파생된 것일 수 있어 "예측"이라기보다
     "동시 관측"으로 해석해야 할 수 있음 — 아이디어2에서 이미 확인한
     "동행이지 선행 아님" 프레임과 일관되게 해석할 것.
   - 라벨 발생 자체가 드문 이벤트(class imbalance)일 가능성이 높아, 단순
     accuracy가 아니라 Precision/Recall/AUC 중심으로 봐야 함.

## 아이디어 5: 일 단위 관측

### 왜 지금 못 하는가
현재 패널은 월별 스냅샷(기준년월)만 있다. 월중에 잔액이 며칠 만에 급락했다가
회복되는 패턴은 월말 잔액만으로는 아예 보이지 않는다 — 월별 데이터가 잡아낼 수
있는 건 "이번 달 평균적으로 압박이 있었다" 정도이지, "이번 달 셋째 주에 무슨
일이 있었다"는 안 보인다.

### 일 단위 데이터가 확보되면 무엇이 가능해지는가

1. **월중 최대낙폭(intra-month drawdown) 지표**: 일별 요구불예금잔액의
   (월초 대비, 또는 월내 최고점 대비) 최대 하락폭·하락 지속일수를 계산.
   월말 스냅샷 기준 지수보다 훨씬 빠르게, 그리고 훨씬 민감하게 압박 시작점을
   포착할 수 있음(예: 월말엔 회복됐지만 월중 15일간 잔액이 바닥을 쳤던 법인을
   구분 가능).

2. **경보 리드타임 재계산**: 아이디어2의 "리드타임"을 월 단위가 아니라 일
   단위로 재정의 가능 — "월말 집계"가 아니라 "그 거래가 찍힌 당일" 기준으로
   경보가 뜨므로, 공식 통계(익월 공표) 대비 리드타임이 지금의 "월말+며칠"
   가정보다 훨씬 더 커질 가능성이 높음(단, 실제로 몇 주가 되는지는 일 단위
   데이터 없이는 추정만 가능하고 확정할 수 없음).

3. **필요 데이터 요건**: 일별 요구불예금 잔액(또는 최소 일별 입출금 거래
   내역)이 있어야 함. 현재 월별 집계 파이프라인과는 별도의 원장(거래) 데이터
   접근이 필요할 것으로 예상.

4. **분석 설계 방향(개략)**:
   - 일별 잔액을 월별로 리샘플링해 "월중 변동성" 지표(표준편차, 최대낙폭 등)를
     파생 → 이걸 기존 월별 압박지수에 추가 변수로 결합.
   - 월중 변동성이 큰 법인이 다음 달 실제로 하락국면 반응을 보이는지 LP로 검증
     (아이디어3과 동일한 방법론 재사용 가능).

이 두 항목은 데이터가 확보되는 대로, 이미 만들어둔 `financial_pressure_signals.py`의
헬퍼(`merge_exact_lag`, `merge_exact_lead`, LP 추정 로직)를 그대로 재사용해
확장하면 된다 — 새 방법론을 새로 설계할 필요는 없을 것으로 예상됨.
